Self-service Oracle Cloud sandboxes that delete themselves

Cloud sandboxes take a ticket and a week to get, and nobody ever deletes them. This builds them from a chat inside your own OCI tenancy — and destroys them when their time is up.

What it does

You describe the environment you need in plain English. The assistant plans the OCI resources, prices them from Oracle's published price list, provisions them with Terraform through OCI Resource Manager, and hands back the URLs and credentials. Each sandbox carries a lifetime of 1 to 30 days and a budget, and a reaper destroys it when the time expires.

Sandboxes that clean themselves up

The reason nobody deletes a cloud sandbox is that deleting it is somebody's job and nobody's priority. Here it isn't a job. Every environment is created with an expiry and a budget. When the clock runs out the stack is destroyed, and every card has a Destroy button for sooner.

Nothing leaves your tenancy

The install is a single OCI Resource Manager stack. The application, the container-instance workers, and the calls to OCI Generative AI all run inside your own account. Users sign in to the app with their own login and need no OCI account of their own.

Credentials never reach the model. When a stack needs a password, the assistant asks for it in a field on the page. The value goes to the resource, not to the AI. Image builds run inside OCI with kaniko, so no laptop ever holds cloud credentials.

Moving an AWS stack to Oracle Cloud

Describe your AWS setup and it maps each piece, then builds it:

  • S3 → OCI Object Storage
  • AWS Glue jobs → Spark on OCI Data Flow
  • Glue Data Catalog → OCI Data Catalog
  • Airflow → stays Airflow, so your DAGs run unchanged
  • Lambda → OCI Functions, code unchanged

Honest pricing

Every proposal comes with a cost table built from Oracle's live price list, broken down per component, with free allowances and per-use services called out. A paid Autonomous Database runs roughly $500 a month while it exists, so the assistant defaults to pay-per-use pieces and prices the database as an option you can drop.

How it is built

  • Terraform on OCI Resource Manager for the install and for every sandbox. No local tooling required.
  • Oracle APEX on an Autonomous Database is the application and the control plane. The assistant runs inside the database and calls OCI Generative AI.
  • Container instances as workers. They turn requests into stacks and build images inside OCI with kaniko.
  • Select AI enabled on every database, so any table can be queried in plain English.
  • An end-to-end suite runs inside OCI, builds every sandbox type for real, verifies it live, then destroys it.

Installing it

One Resource Manager stack, about 15 minutes. It needs a tenancy administrator and a Pay-As-You-Go or paid Oracle Cloud account. Read the prerequisites first — they list exactly what the install creates and what it grants.

Questions people ask

How do I give developers self-service environments on Oracle Cloud?

Install this into your tenancy. Developers ask for what they need in a chat instead of raising a ticket, and get a running environment with links and credentials in minutes rather than a week.

How do I stop unused Oracle Cloud sandboxes running up a bill?

Give every environment an expiry when it is created. Here that is built in — 1 to 30 days plus a budget, enforced by a reaper that destroys the stack automatically.

Is it really open source?

Yes. The Terraform for the install and for every sandbox type is public on GitHub, so you can read exactly what gets created in your tenancy and what permissions it is granted before you run anything.
